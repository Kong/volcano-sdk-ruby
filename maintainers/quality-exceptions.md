# Quality exceptions

| Rule | Scope | Rationale | Evidence |
| --- | --- | --- | --- |
| Steep `Ruby::MethodDefinitionMissing` | `Volcano::Error::VolcanoError#status`, `#code`, and `#retry_after` in `lib/volcano/errors.rb` | Steep cannot infer methods created by `attr_reader`; RuboCop `Style/TrivialAccessors` requires these readers to use `attr_reader`. The three-method `@dynamic` annotation leaves their public RBS types and consumer checks active. | [Steep's documented accessor annotation](https://github.com/soutaro/steep#2-write-ruby-code); removing this annotation produces exactly three `Ruby::MethodDefinitionMissing` diagnostics under `bundle exec steep check --jobs 1`. |
| Steep `Ruby::MethodDefinitionMissing` | The eight instance methods and two class methods generated by `Data.define` for `Volcano::SignUpResult` in `lib/volcano/sign_up_result.rb` | Steep cannot infer methods generated by `Data.define` when the class is reopened to check its initializer. The exact-method `@dynamic` annotations preserve the public RBS types and consumer checks. | [Steep's documented dynamic-method annotation](https://github.com/soutaro/steep#2-write-ruby-code); removing both annotations produces exactly ten `Ruby::MethodDefinitionMissing` diagnostics under `bundle exec steep check --jobs 1`, while the annotated target has no diagnostics. |
| Steep `Ruby::MethodDefinitionMissing` | Generated methods listed by `@dynamic` for `StorageObject` and `StoragePage` in `lib/volcano/storage_models.rb`, and `UploadSessionRequest`, `UploadPartRequest`, `UploadSessionReference`, `UploadSession`, `UploadPart`, and `UploadSessionStatus` in `lib/volcano/storage_upload_models.rb` | Steep cannot infer `Data.define` methods when these classes are reopened so their freezing and validation initializers can be checked. | Steep `Ruby::MethodDefinitionMissing` | Generated `Data.define` methods listed by `@dynamic` on `Realtime::PresenceInfo`, `PostgresBatchConfig`, `PostgresChange`, and `BroadcastDelivery::PublicationContext` in `lib/volcano/realtime.rb`, `lib/volcano/realtime/postgres_batch.rb`, `lib/volcano/realtime/postgres_changes.rb`, and `lib/volcano/realtime/broadcast_delivery.rb`; `Realtime::Presence#get_presence_state` alias, `Realtime::ServerError#code` reader, and `Realtime::Channel#name` reader | Steep cannot infer these generated, aliased, or accessor methods while checking their validated initializers and callers. Each annotation names only the methods supplied at runtime; their RBS declarations remain concrete. | [Steep's dynamic-method annotation](https://github.com/soutaro/steep#2-write-ruby-code); the realtime target uses `Steep::Diagnostic::Ruby.all_error`, and `bundle exec steep check --group=realtime --validate=project --jobs 1` checks these files. |
| Steep `RBS::ModuleSelfTypeError` / `Ruby::MethodDefinitionMissing` | Exact sibling-provided methods listed by `@dynamic` on realtime mixins in `lib/volcano/realtime.rb` and `lib/volcano/realtime/{broadcast_delivery,channel_callbacks,channel_lifecycle,connection,connection_callbacks,lifecycle,postgres_batch,postgres_changes,postgres_delivery,postgres_expansion,presence,presence_state,protocol_dispatch,protocol_io,protocol_lifecycle,protocol_publication_dispatch,protocol_recovery,protocol_recovery_dispatch,reconnect}.rb` | RBS self-type interfaces cannot require private methods supplied by sibling mixins. Each mixin instead imports an exact typed development interface; `@dynamic` acknowledges only the methods supplied by the composed runtime class. Method bodies, argument and result types, and full-project signature validation remain checked. | RBS 3.10.4 rejects private interface members; a private provider before a consumer still produces `RBS::ModuleSelfTypeError` under `bundle exec steep check --group=realtime --validate=project --jobs 1`. The typed-interface annotations clear those diagnostics without changing method visibility. |
| Steep `Ruby::MethodDefinitionMissing` | `Realtime::Core#__send__` in `lib/volcano/realtime.rb` | The development signature overloads inherited `Object#__send__` for three exact private calls; Steep does not associate those overloads with the inherited method while checking the mixin. The annotation adds no method or public signature. | `bundle exec steep check --group=realtime --validate=project --jobs 1` checks the exact overloads and all callers. |
